# Планер — личный планер дня в одном Cloudflare Worker

PWA + Telegram Mini App + голосовой Telegram-бот + выгрузка в Notion Calendar.
Всё живёт в одном Worker'е на бесплатном тарифе Cloudflare. Без серверов, подписок и n8n.

- **Планер дня** — план блоками по времени, быстрый ввод («созвон 1.5ч в 16:00 завтра #работа !»), «Спланировать день» с автопланом, «Завершить день», привычки, сферы, цикл 12 недель.
- **Синк везде** — телефон, компьютер и Telegram Mini App видят одни данные; работает офлайн, правки долетают за секунды (last-write-wins, pull по серверной ревизии).
- **Голосовой бот** — наговариваешь задачи в Telegram, Whisper расшифровывает, Llama раскладывает по времени, дню и длительности.
- **Напоминания-будильник** — когда наступает время задачи: звуковой сигнал в приложении (настройка «за сколько предупреждать») + сообщение от бота в ту же минуту, даже с закрытым приложением.
- **Notion Calendar** — задачи с датой уходят в Notion каждые 5 минут (односторонний синк).

## Установить себе

### Что важно знать

- **Данные изолированы**: каждый Telegram-пользователь видит только свои задачи. Если друг пользуется вашим ботом — у него свои данные, у вас свои. Отдельный деплой нужен только для полного контроля (своя база, свой бот, свои лимиты).
- **Каждому свой набор**: аккаунты GitHub, Cloudflare и Telegram создаются самостоятельно; свой бот через @BotFather; своя база D1. Токен бота — только в секретах Cloudflare.
- Нужен **Node.js 20+** только для терминального пути (Вариант Б) и локальной разработки. Вариант А — полностью в браузере.

### Вариант А — через браузер, ничего не устанавливая (~15 минут)

1. **Форкните репозиторий** (кнопка Fork на GitHub) — код окажется в вашем аккаунте.
2. **Создайте базу**: Cloudflare Dashboard → **Storage & Databases → D1 → Create** → имя `planner` → откройте её → скопируйте **Database ID** (UUID).
3. **Впишите ID**: в своём форке на GitHub откройте `wrangler.toml` → карандаш (Edit) → замените значение `database_id = "…"` на скопированный UUID → Commit changes.
4. **Создайте Worker**: Cloudflare → **Workers & Pages → Create → Import a repository** → выберите форк.
   - Build command: `npm run build`
   - Deploy command: `npx wrangler deploy`
   - Root: `/`
5. **Токен бота**: Telegram → @BotFather → `/newbot` → имя и username → скопируйте токен → в Worker: **Settings → Variables and Secrets → Add** → имя `BOT_TOKEN`, тип **Secret**, значение — токен.
6. Нажмите **Deploy** и дождитесь Ready. Откройте `https://<имя-worker'а>.<ваш-аккаунт>.workers.dev/api/health` → должно быть `{"ok":true}`.
7. **Подключите бота**: откройте планер из чата с вашим ботом в Telegram (кнопка меню) → он сам авторизует вас → **Настройки → Telegram-бот → «Подключить бота к планеру»** (вебхук, кнопка меню и команды ставятся автоматически, статус видно под кнопкой).
8. **Необязательно**: Notion (Настройки → Notion → секрет интеграции + ссылка на страницу), ключ для браузера на компьютере (Настройки → Ключ для браузера).

### Вариант Б — через терминал одной командой

```bash
git clone https://github.com/veslav02-jpg/Golosovoy_Planer.git planner
cd planner
npm install
npx wrangler login     # откроет браузер
npm run setup
```

`npm run setup` сам: найдёт или создаст базу D1 «planner», впишет её Database ID в `wrangler.toml`,
спросит `BOT_TOKEN` (и опционально сгенерирует `SERVICE_KEY`), соберёт фронт и задеплоит Worker.
В конце напечатает адрес — дальше те же шаги 7–8 из Варианта А.

Если форкнете и будете деплоить через Workers Builds — закоммитьте изменённый `wrangler.toml`
и запушьте, Cloudflare пересоберёт сам.

### Проверка после деплоя

- [ ] `/api/health` отвечает `{"ok":true}`.
- [ ] Голосовое боту «завтра в 11 созвон с клиентом на час» → бот ответил списком → задача в планере.
- [ ] Задача с временем через пару минут: планер (открытый) прозвенел, бот прислал «⏰ Сейчас по плану».
- [ ] Задача, добавленная на телефоне, появилась на компьютере (и наоборот).
- [ ] Через 5 минут задача с датой видна в Notion Calendar.

## Локальный запуск (разработка)

```bash
npm install
npm run build
npm run dev:local        # билд + wrangler dev на http://127.0.0.1:8787
node scripts/devkey.mjs  # ключ для входа в браузере (локальный тестовый пользователь)
```

Локально (`wrangler.local.toml`) нет биндинга AI — бот и Notion вернут понятную ошибку,
всё остальное работает. Демо-данные: Настройки → Демо-данные.

Тесты: `npm test` — 43 теста (парсер, автоплан, повторы, очки, API на node:sqlite,
бот и Notion с подменой внешних API).

## Лимиты (бесплатный тариф Cloudflare)

| Сервис | Лимит | Для одного человека |
|---|---|---|
| Workers | 100 000 запросов в сутки | с огромным запасом |
| D1 | 5 ГБ, 5 млн чтений и 100 000 записей строк в сутки | с огромным запасом |
| Workers AI | 10 000 нейронов в сутки, сброс в 00:00 UTC (03:00 по Москве) | хватает на ежедневные голосовые |

## Безопасность

- Токен бота и `SERVICE_KEY` — только в секретах Cloudflare. Никогда в коде, `wrangler.toml` или репозитории
  (в `wrangler.local.toml` лежит только фиктивный токен для локального запуска).
- Засветил токен — сразу перевыпусти его в @BotFather через `/revoke` и обнови секрет.
- Ключ для браузера и секрет Notion никому не показывай: это доступ к твоим задачам.
- Авторизация Mini App: подпись initData проверяется HMAC по токену бота (поддержаны клиенты
  с полем `signature` и без него).

## Частые ошибки

| Симптом | Причина и решение |
|---|---|
| Ошибка деплоя 10021 про database_id | В `wrangler.toml` не ваш Database ID (или заглушка). Вставьте UUID своей базы D1. |
| После деплоя пропал токен бота | Добавлен как обычная переменная. Удали и добавь заново с типом **Secret**. |
| Worker падает на запросах к базе | database_id чужой/несуществующий. Возьмите ID из своего D1. |
| Бот молчит на сообщения | Не нажата кнопка «Подключить бота к планеру» в настройках — вебхук не поставлен. Статус виден там же. |
| «Не смог расшифровать голосовое: …neurons…» | Суточный лимит Workers AI — сброс в 03:00 по Москве. Текстом задачи продолжают работать. |
| Mini App не открывается из бота | URL в BotFather без `https://` или с опечаткой (но обычно кнопка меню ставится сама через «Подключить бота»). |
| На компьютере просит ключ | Это нормально: ключ выдаётся при первом входе из Telegram. Mini App → Настройки → Ключ для браузера. |
| Задачи не доходят в Notion | Страница не подключена к интеграции (··· → Connections) или у задачи нет даты. |

## Как это устроено

```
┌────────────────────────────────────────────┐
│                Cloudflare Worker           │
│  dist/* (React PWA)  +  /api/* (worker.js) │
│                                            │
│  /api/auth/telegram  HMAC initData → ключ  │
│  /api/tasks/sync     last-write-wins       │
│  /api/items/sync     last-write-wins       │
│  /api/pull?since=rev push/pull по ревизии  │
│  /api/telegram/webhook  голос/текст → AI   │
│  /api/notion/connect   база «Планер»       │
│  cron */5 мин: Notion + напоминания        │
└───────────────┬────────────────────────────┘
                │ D1 (tasks, items, keys, secrets)
```

- **Синк**: локальная копия главная, правки мгновенно и офлайн; push грязных записей раз в секунду,
  pull при фокусе, возврате в сеть и раз в 30 с; удаления — надгробия; отметки привычек — детерминированные
  id `hl:<привычка>:<дата>`.
- **Авторизация**: initData Telegram проверяется HMAC по токену бота; тот же ключ вставляется в браузере;
  внешние автоматизации — `X-Service-Key` + `X-Telegram-User-Id`.
- **Схема БД** создаётся кодом при первом запросе (CREATE TABLE IF NOT EXISTS + ALTER TABLE для новых колонок).

Структура:

```
server/          Worker: worker.js, api.js, bot.js, notion.js, cron.js, db.js, auth.js, util.js
src/             React: экраны (components/), стор (store.js), синк (sync.js)
src/lib/         логика: парсер ввода, автоплан, повторы, очки, экспорт/импорт, даты
tests/           node:test: логика + API на node:sqlite + бот/Notion с подменой API
scripts/         setup.mjs (автоустановка), devkey.mjs (локальный ключ)
wrangler.toml    прод-конфиг (database_id вашей базы)
wrangler.local.toml   локальный конфиг без AI
```
